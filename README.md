# Kotlin Text Editor — IS2205 Mini-Project

A lightweight mobile text editor for developers and technical writers, written in
**pure Kotlin** (native Android, XML layouts). It supports Kotlin & Markdown syntax
highlighting, local file management, crash recovery, undo/redo, and a
**delta-based version control system** that never duplicates file content.

---

## 1. How to build and run

1. Open **Android Studio** → *Open* → select the `KotlinTextEditor` folder.
2. Wait for the Gradle sync to finish (needs internet the first time).
3. Press **Run ▶** with an emulator or a connected phone (Android 8.0 / API 26 or newer).
4. To create the APK for submission: **Build → Build App Bundle(s) / APK(s) → Build APK(s)**.
   The APK appears in `app/build/outputs/apk/debug/app-debug.apk`.

On first launch the app creates two demo files (`Welcome.md`, `HelloWorld.kt`)
so every feature can be demonstrated immediately.

## 3. How each requirement is implemented

### Editor engine & UI
- **New / Open / Save / Save As / Recent files** — `FileRepository` stores all documents
  in the app's private internal storage (`files/documents/`), so no permissions are
  needed. The sidebar (navigation drawer) lists recent files (`RecentFilesStore`).
  *Save As* offers an **encoding** choice (UTF-8 / UTF-16 / ISO-8859-1); the chosen
  encoding is remembered per file in the database.
- **Word wrap toggle** — `editor.setHorizontallyScrolling(...)` switches between
  wrapping and horizontal scrolling.
- **Search & replace** — a hidden panel above the editor; find-next wraps around,
  replace-all is applied as one edit so a single Undo reverts it.
- **Undo / Redo** — see `UndoRedoManager`: every text change is recorded by a
  `TextWatcher` as *(position, removedText, insertedText)*. Undo replaces the
  inserted text back with the removed text; redo does the opposite. A flag
  (`isPerformingUndoRedo`) prevents undo operations from recording themselves.

### Syntax highlighting
- Android `EditText` text is a *Spannable*: we attach `ForegroundColorSpan` /
  `StyleSpan` objects to ranges of characters.
- After each edit we wait 250 ms (debouncing), remove old spans, run regular
  expressions, and color every match (`SyntaxHighlighter.colorMatches`).
- **Kotlin**: keywords are loaded from `assets/kotlin_keywords.txt` (keyword file, as
  the spec suggests) plus patterns for strings, comments, annotations, numbers.
  Strings and comments are applied **last** so they win inside overlaps.
- **Markdown**: patterns for headings, bold, italic, inline code, links, bullets,
  quotes. The **preview panel** (menu → Markdown preview) is rendered by the
  Markwon library.

### Local history & fault tolerance
- `AutoSaveManager` copies the editor buffer into `cache/autosave_buffer.txt`
  **every 10 seconds** (and on `onPause`).
- Normal exit → backup deleted. Crash / process kill → backup survives, and the
  next launch shows a *"Recovered unsaved work"* dialog offering to restore it.
- Try it: type text without saving, then kill the app from Android Studio's
  Logcat "terminate" button (or `adb shell am kill com.example.texteditor`), reopen.

### Delta-based version control (the core requirement)
- **Storage rule (no duplication):**
  - Snapshot **1** stores the full text (`FileVersion.baseContent`) — the *base*.
  - Snapshot **N > 1** stores **only a unified-diff patch** (`FileVersion.patchText`)
    computed against version N-1 with **java-diff-utils**.
  - Rebuilding version K = base text + apply patches of versions 2..K in order
    (`VersionControlManager.rebuildText`).
- **Room/SQLite** persists the two tables `tracked_files` and `file_versions`.
- **Diff view** — `DiffActivity` rebuilds versions N-1 and N and shows a
  line-by-line comparison (green = added, red = removed). The version list even
  shows *how* each version is stored ("full text" vs "delta patch only") to make
  the storage saving visible in the demo.
- **Rollback** — *Restore* rebuilds the chosen version's text, puts it in the
  editor and writes it back to the file. History is kept; restoring then
  snapshotting simply creates a new version on top.
- **Read-only flag** — menu → *Read-only* removes the EditText's key listener
  (typing blocked, copying still works), blocks Save/Replace, and persists the
  lock in the `tracked_files` table.

## 5. Likely viva questions (and where the answer lives)

- *Why don't you duplicate the file for each version?* → `FileVersion.kt` comment;
  only version 1 stores full text, later versions store unified-diff patches.
- *How do you rebuild an old version?* → `VersionControlManager.rebuildText`:
  base + patches applied in order.
- *How does highlighting work?* → spans on the `Editable`; regex matches get
  `ForegroundColorSpan`s; debounced re-highlight after edits.
- *How does undo work?* → stack of `(position, removed, inserted)` operations
  recorded by a `TextWatcher`.
- *What happens when the app crashes?* → 10-second backup in the cache dir;
  restore dialog on next launch (`AutoSaveManager`, `checkForCrashBackup`).
- *Why Room and not raw SQLite?* → compile-time checked queries, less boilerplate;
  Room generates the SQL implementation of `VersionDao` at build time.
- *Why coroutines (`lifecycleScope.launch`)?* → database and file operations must
  not block the UI thread; `suspend` DAO functions run on a background thread.
- *What happens on screen rotation?* → state (file name, flags) is saved in
  `onSaveInstanceState`; the text is restored by Android; the watcher is
  suppressed during the restore so it is not recorded as an edit.

## 6. Notes / limitations (be honest in the viva!)

- Files live in the app's private storage (as the spec's storage logic describes);
  there is no system file picker. This keeps the app permission-free.
- The optional Kotlin auto-formatter was not implemented (marked *optional* in the spec).
- Undo history is kept per session (in memory), max 500 steps — it is cleared when
  another file is opened, which matches the spec ("during the active session").
